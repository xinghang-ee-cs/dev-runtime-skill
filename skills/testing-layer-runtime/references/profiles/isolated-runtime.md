# 容器、插件与子进程检查

仅存在对应执行机制时加载。本 Profile 补充检查方向，不定义产品阈值、授权或新生命周期。

- 从已确认合同和当前部署配置取得 CPU、内存、进程数、并发、执行时间和输出上限；缺少标准时明确待决，不自行赋值。对确实不适用的资源逐项说明理由。
- 区分配置声明、目标实例实际生效值和受控超限后的行为；只有配置文件中写了限制，不能证明运行实例受限。容器在本地未按实际部署方式运行，不能代替目标部署证据。
- 核对插件/进程实际获得的环境变量键名、凭据挂载范围、只读性、宿主目录、临时目录和跨插件/租户可见范围。用测试凭据/canary 或脱敏元数据证明边界，禁止读取真实秘密正文。主进程需要某凭据不等于所有插件都应获得它。
- 在获准隔离环境验证超时、内存/进程边界、崩溃退出、取消和重启；检查主服务是否仍可用、失败是否隔离、进程树/文件/连接是否回收。实际故障注入范围、停止条件和清理策略必须明确。
- 核对健康检查失败会阻止接流量或触发合同要求的恢复；只看到容器 running/进程 PID 不算服务就绪。
- 部署变更检查挂载、配置和镜像 revision；升级/回滚后确认状态与持久数据兼容。Testing 只核验证据，实际部署/回滚由发布流程执行。
- 将可复现隔离缺陷的测试纳入 CI，核对对应 job 实际执行；真实目标的生效验证仍单独保留。
