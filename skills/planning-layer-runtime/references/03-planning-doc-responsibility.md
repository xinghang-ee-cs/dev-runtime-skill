# 流程梳理阶段：文档职责与最小输出

## 1. 文档结构

规划文档使用规范目录，不默认全量生成。

以下文件名是当前建议命名，不是跨 skill handoff 的稳定协议。

跨 skill handoff 必须按文档职责承接，例如 `Development Landing Checklist`、`Capability Governance`、`Execution and Integration Record`、`Acceptance and Retrospective Record`。

根据需求特征动态装配必要文档；L 级跨模块变更或用户明确要求完整规划时，可使用完整建议链路：

```text
00-需求背景与目标.md
01-需求范围与验收标准.md
02-业务域模型.md
03-用户场景与交互流程.md
04-功能拆解与边界说明.md
05-前端页面与UI交互设计.md
06-数据模型与状态流转.md
07-接口设计与前后端契约.md
08-权限与异常边界说明.md
09-架构设计与关键决策.md
10-外部能力与集成治理.md
11-测试方案与验收用例.md
12-风险、依赖与待确认项.md
13-开发任务拆分与落地清单.md
14-开发执行与联调变更记录.md
15-验收结果与复盘.md
```

动态装配规则由 `06-planning-capability-governance.md#15-文档装配规则` 定义。

planning handoff 给执行 skill 时，必须显式输出职责到路径的映射，禁止让执行 skill 通过编号猜测文件。

## 3. 文档结构化依赖模板

每份文档必须包含：

```markdown
## 上游 SoT

- xx-文档名.md#ID

## 下游输出

- xx-文档名.md#ID

## 禁止定义内容

- ...
```

## 4. 阶段分界

00 到 13 属于流程梳理阶段，planning-layer-runtime 的职责截止于开发开始前。

14 属于 long-task-orchestrator 的开发与自动化执行记录阶段。

15 属于 testing-layer-runtime 接管后的验收与复盘阶段。

## 5. Planning Runtime Final Output

Planning Runtime 最终输出：

```text
1. Planning Context
2. Formal SoT Documents
3. assembled_documents
4. handoff_role_mapping
```

Long Runtime 对接规则：

- 只能读取 `handoff_role_mapping`。
- 禁止通过编号猜测文件。
- 禁止自行推断职责。
- 禁止缺失 role 时继续 implementation。
- `handoff_role_mapping` 属于 Runtime Contract，不属于业务 SoT。
