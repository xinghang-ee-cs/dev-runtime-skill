# 流程梳理阶段核心规则

## 1. 目标

流程梳理阶段的目标不是写代码，而是建立 AI 可稳定理解的开发上下文。

必须确认：

- 为什么做
- 做什么
- 不做什么
- 业务域是什么
- 谁使用
- 角色拥有什么权限
- 数据可见范围是什么
- 怎么流转
- 数据怎么变化
- 接口怎么协作
- 什么情况算完成

## 2. 最高优先级规则

- 不允许隐式猜测需求、范围、权限、数据结构、接口行为和状态流。
- 高风险不确定项必须停止确认。
- 低风险不确定项允许带假设推进，但必须显式标注。
- 上游文档未确认时，下游文档不得落正式正文。
- 每份文档只负责自己的职责，不允许跨文档写内容。
- 下游发现上游错误时，必须回到上游修正。
- 每份正式文档必须单独生成、单独确认；当前文档未确认前，不得生成下一份正式文档。
- 文档结论必须可追踪到已确认信息。
- 未确认内容不得写成事实。
- 所有关键实体必须具备唯一 ID。
- 所有关键结论必须可追踪到来源。
- 禁止多个文件定义同一事实。
- 状态流必须显式定义。
- 所有跨模块变更必须具备影响分析。
- 面向非专业用户的提问必须使用业务白话，不得直接抛出专业术语。
- UI/交互高风险项未确认时，不得生成依赖该 UI 的开发任务。

## 3. 结构化 Runtime 规则

关键实体：

- 需求
- 流程
- 状态
- 接口
- 权限
- 风险
- 测试
- 任务

规则：

- 结论格式：`结论 -> 来源`
- SoT 唯一：同一事实只能由一个文件定义
- 状态流：必须定义来源、去向、非法迁移、回滚规则
- 跨模块变更：必须定义影响文档、接口、状态、权限、测试、租户隔离、缓存、历史兼容

## 4. 高风险不确定项

以下内容不明确时，必须停止，不得继续落正式正文：

- 权限规则
- 删除规则
- 数据归属
- 租户隔离
- 数据结构
- 状态流转
- 接口契约
- UI/交互高风险项
- 审计规则
- 旧逻辑是否保留
- 外部系统真实调用
- 安全、合规、计费、审批相关逻辑

停止后允许输出：

```text
当前理解
-> 阻塞问题
-> 推荐方案
-> 建议确认路径
```

## 5. 低风险不确定项

以下内容不明确时，可以基于假设继续推进：

- 按钮文案
- 空状态文案
- loading 文案
- 图标选择
- 局部样式
- 展示顺序
- 变量命名
- 非核心组件命名
- 低风险 UI 细节

前提：

- 核心页面布局、操作路径、跳转关系、状态反馈、异常态、空状态、加载态、移动/桌面适配和视觉风格已确认。
- 未确认核心 UI/交互时，上述内容不得按低风险假设进入 UI 依赖开发任务。

但必须显式标注：

```text
假设：……
风险等级：低
待确认：是
影响范围：……
回收时机：验收前确认
```

## 6. 文档依赖链

默认链路为：

```text
目标
-> 范围
-> 业务域
-> 角色
-> 权限
-> 数据可见性
-> 用户流程
-> 功能边界
-> 数据模型
-> UI设计
-> 接口契约
-> 权限异常
-> 架构决策
-> 外部能力治理
-> 测试方案
-> 风险依赖
-> 开发任务
```

规则：

- 下游不得反向覆盖上游。
- 代码实现不能反向定义需求。
- 验收结果不能替代测试方案。
- 执行记录不能替代任务清单。
